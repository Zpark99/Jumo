### 공통 패턴

- **"만들었다"와 "돌아간다"를 구분하지 않음** — 6·7. 자동화를 만든 PR에서 이슈를 닫고 첫 실행 결과를 안 봄. 두 번 다 **운영 DB의 날짜 컬럼**(`updated_at`·`fetched_at`)이 신호였다. → CLAUDE.md 8단계 "첫 스케줄 실행 결과까지 확인 후 닫기", `[운영]` 이슈는 증거(스크린샷·수치) 첨부 후 닫기.
- **로컬 ≠ 운영** — 2·3·7. 코드 밖 설정(env·리디렉션 URL·cron secret)이 환경별로 따로 살고, env는 **새 배포에만** 적용된다. → 08 체크리스트 "운영 설정" 절, 릴리스 PR의 "Production에 붙었는지" 1번 항목.
- **유저 1명이라 드러나지 않음** — 4·8·9. 0원 체결은 US quote 행이 없어서, 랭킹 빔은 타 유저가 없어서, 뷰 노출은 비로그인으로 REST를 칠 사람이 없어서 조용했다. → 데모 계정(#178)을 만든 뒤에야 8이 나왔고, 권한을 **역할별 JWT로 직접 조회**(#180 표)하는 방식이 9를 찾았다.
- **플랫폼 기본값이 의도를 덮음** — 5·9. Supabase의 함수 자동 grant, 뷰의 기본 grant·정의자 기본값. 마이그레이션에 쓴 `revoke … from public`은 의도였지 결과가 아니었다. → 회수는 세 역할 명시, 적용 후 `pg_proc.proacl`·`role_table_grants` 실측.
- **결정이 막히면 코딩 주간에 영원히 밀림** — #32 82일, #38 75일, #20 74일, #39 72일, `layout.tsx` 3회, CLAUDE.md 승격 규칙 4회. "다음 주 액션"에 네 번 적어도 안 움직였고, **"코딩 이슈를 만들기 전에 결정 이슈부터"** 순서를 바꾼 10-09~10 이틀에 전부 닫혔다.
